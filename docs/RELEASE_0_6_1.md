# Диковерия LAB — релизный пакет 0.6.1 (кандидат)

Базовый коммит main: `bccc9e0f71aacdbc25d8dc87e691cedf125de606` (PR #11 объединён после успеха CI).
Рабочая ветка: `release/0.6.1-integrated-lab-core-20261112`.
Основное ТЗ: Issue #4, первичный аудит: Issue #3, раннее ТЗ: Issue #1.

## Контракт учёта

* `cultures.quantity` — единственный **операционный остаток** только в явной `quantity_kind`. Если внесено несколько независимых положительных исходных показателей, тип `Не уточнено`, а перемещения/списания запрещены до ручного подтверждения типа **и фактического количества**. Никакого автоматического перевода эксплантов в побеги или растения.
* `culture_measurements` содержит независимые nullable измерения `explants`, `shoots`, `plants`, `contaminated`. SQL `NULL` означает не измерялось, `0` — измеренное отсутствие. Поле `record_kind` разделяет `baseline` и `observation`. Наблюдения не меняют остаток.
* `events`, `assessments`, `culture_measurements` сохраняются в исходном формате. Единая хронология `unifiedJournal` собирает их при чтении, помечает источник и убирает очевидные пары старого события и старого измерения. Архивный `healthy_qty` **не интерпретируется** как число растений или побегов.
* Списания, разделения и объединения уже используют атомарный `lab_operations` + `operation_changes`. Для смены среды добавлены операция, снимок и событие в той же транзакции. Ручное подтверждение неизвестного типа — отдельная аудируемая операция.
* При разделении/объединении можно выбрать утверждённую версию рецептуры напрямую; партия приготовления необязательна. Если выбранные рецепт и партия не совпадают, транзакция отклоняется. Разные рецептуры родителей не объединяются в одну автоматически. Дочерние связи происхождения сохраняются.
* Смена рецептуры без партии сбрасывает прежнюю привязку к партии. Редактирование контейнера не оставляет партию с рецептурой другой версии. Версии состава создаются отдельно, включая `sugar_g_l` и `agar_g_l`; старые версии не меняются.

## SQLite v8 и аудит

* Данные схемы v7 сохраняются, старая структура не удаляется. Только добавление `record_kind` и новой `culture_audit` с триггером на изменения `quantity`, `quantity_kind`, `status`, `medium_batch_id`, `medium_recipe_id`, `stage`, `location`.
* Триггер запоминает старое и новое значения в **одной SQLite-транзакции**. Изменения, связанные с `lab_operations`, дополнительно получают `operation_id`. При миграции/восстановлении из прежней версии записывается только достоверное **текущее состояние**, без выдуманной истории «до».
* При восстановлении JSON/ZIP принимаются форматы v4–v8. Старые архивы не обязаны иметь таблицу аудита. Для v8 порядок восстановления учитывает внешние ключи; вызываются `foreign_key_check` и `integrity_check` до коммита; ошибка откатывает БД. Экспорт выполняется в согласованной транзакции чтения.
* Фотографии продолжают передаваться вместе с ZIP через `LabBackup`, без изменения протокола подписывания и Android applicationId.
* Версия релизного кандидата: `0.6.1-rc1`; до приёмки/CI это не стабильная `0.6.1`.

## Контрольный тестовый маршрут

1. Обновить копию реальной v7 базы на v8; сравнить количество исходных `cultures`, `events`, `assessments`, `culture_measurements`, `recipes`, `recipe_parts`, `batches` до/после. `PRAGMA foreign_key_check` пуст.
2. Создать контейнер с несколькими типами измерений: операционный тип «Не уточнено»; подтвердить вид и количество ручным действием; проверить снимок `before/after` и историю.
3. Создать наблюдения с заметкой, нулём и пустым числом; проверить разницу NULL/0, единый журнал, отсутствие стартовой записи в числе повторных наблюдений.
4. Разделить/объединить несколько контейнеров, указать новую версию среды без партии; проверить `culture_links`, остатки, рецепт дочернего контейнера, историю и отсутствие незавершённых транзакций.
5. Попробовать назначить противоречащую партию и рецептуру; операция должна целиком откатиться.
6. Записать потери и исправление количества. Убедиться в одновременном создании операции, события, снимка и аудита.
7. Создать ZIP v8, восстановить его, сопоставить записи и фотографии; повторить с копиями v4, v5, v6 и v7; специально повредить внешний ключ и проверить отказ без частичного восстановления.
8. Проверить Android unit tests, debug build, UI обновления, русский текст, работу на реальном телефоне.

**Автоматические тесты на PR** проверяют структурную схему, реальный SQL триггера (в SQLite CPython), откат/внешние ключи, аналитику, сборку Kotlin/Android. **Пункты с реальными пользовательскими резервными копиями и физическим Android не подтверждаются автоматически без доступных экземпляров**. Пока они не проверены, выпуск/слияние необходимо оценивать как риск.
