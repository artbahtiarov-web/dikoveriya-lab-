## Экранная архитектура и путь пользователя

`Главная → Коллекция → Сорт → Контейнер → Рост / Среда / Операции / История`.

* **Главная**: живые показатели (количество контейнеров в стерильной культуре, на контроле, в адаптации/росте и просроченные задачи) плюс создание контейнера, коллекция, среда и сканирование, последние контейнеры. Без выдуманной «выживаемости» и другой псевдостатистики.
* **Коллекция**: поиск сорта, порядок по имени/количеству контейнеров, создание сорта, количество реально существующих контейнеров.
* **Сорт**: поиск по коду/месту, фильтры «Все/Активные/На контроле/Архив», переход в конкретный контейнер.
* **Контейнер**: код, название, этап, статус, подтверждённый тип и остаток, место, происхождение; 4 **большие самостоятельные плитки** с реальными обработчиками переходов.
* **Рост**: сохранение измерений и заметок без чисел; `NULL` ≠ `0`; отдельная маркировка исходного замера; график только по фактически заполненным измерениям выбранного типа, исходные и последующие значения не являются доказательством коэффициента размножения. Заметка о сохранении с датой.
* **Среда**: текущая утверждённая версия, документированная история рецептур, смена рецепта с причиной через существующую транзакционную операцию; партия необязательна.
* **Операции**: быстрые действия, ведущие к проверенному `LabActionDialog` с предвыбранным сценарием, список реальных операций. Не обходить проверки единиц биоматериала и остатка в БД.
* **История**: реальный `unifiedJournal`, поиск, категории, период 7/30/90 дней, раскрытие деталей, отображение снимков `culture_audit` с `before/after`, привязка к operation ID.

Старые настройки, справочники, резервные копии, QR-сканер, SQLite, операции и рецептуры сохраняются. В версии 0.7.0 **нет новой миграции SQLite**. Никаких изменений подписывающего ключа / applicationId.

## Back и сохранение данных

* Одна функция `goBack()` управляет стрелкой и `BackHandler` Android. Маршрут хранится как `rememberSaveable(List<String>)`; каждое нажатие Back удаляет **строго один маршрут**, не сбрасывает всю иерархию.
* Нижняя панель показывает контекст открытого экрана и позволяет перейти к другому корневому разделу; возвращение в маршрут не стирает саму базу.
* `rememberSaveableStateHolder` с `SaveableStateProvider(route)` сохраняет форму, поиск, фильтры и `LazyListState` при переходах. Старые вкладки тоже имеют отдельные ключи `legacy:$tab:$subsection`.
* Пользовательские числовые поля, заметки, выбор рецепта и фильтры — `rememberSaveable`. Динамические списки пересадок, источники объединения и участники инцидента теперь сериализуются через `listSaver`/`mapSaver`. После поворота экрана и перехода назад сохранение поддерживается в исходниках; полного теста восстановления после системного уничтожения процесса для всех старых диалогов пока нет. При обычном открытии операций учёт транзакционный и не меняется без сохранения.

## Контроль 360–430dp / увеличенный шрифт

Добавлены Compose Preview-конфигурации:
- 360dp с `fontScale=1.5`: обзор, одноколоночные быстрые действия.
- 390dp с обычным масштабом: обзор, двухколоночные KPI.
- 430dp с `fontScale=1.6`: заголовки и четыре плитки контейнера.

Критерии ручной проверки: заголовки не обрезаются; основной текст не меньше системных уровней; карточки увеличиваются по высоте; кнопки не перекрываются; системный Back и стрелка возвращают на один маршрут; поиск и скролл сохраняются после обратного перехода; поля Growth/Medium не теряются при Back и повторном открытии; длинные названия сортов переносятся; видны статусы, дата сохранения и составные подписи.

**Разграничение фактов:** статические/Unit тесты проверяют маршрут и наличие UI/состояния. Compose Preview сами по себе не являются отчётом о реально просмотренных рендерах. Проверку пикселей/кликов на физических 360–430dp телефонах и увеличенных системных шрифтах без инструмента Android Emulator/устройства считать НЕ подтверждённой.
