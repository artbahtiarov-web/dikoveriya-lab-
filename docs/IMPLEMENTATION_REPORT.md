# Диковерия LAB — повторный аудит и отчёт о реализации

**Дата:** 10.11.2026. **Сборка:** исходники `0.3.0-dev`. **Статус:** пакет к загрузке, Android APK не проверен на GitHub Actions и физическом телефоне.

## Что было обнаружено в старом репозитории

1. **Критично:** в корневом `build.gradle.kts` находился код Android-приложения без версий плагинов. В `app/build.gradle.kts` оставалась `0.1.0`. Это подтверждённая причина красной GitHub Actions сборки: `Plugin [id: 'com.android.application'] was not found`.
2. **Критично:** в исходнике `MainActivity.kt` из v0.2 находилась порча русских строк (`Р...` вместо русских слов). Новый интерфейс написан в UTF-8. Только старые повреждённые значения статусов восстанавливаются в миграции; старые произвольные заметки, если были записаны с порчей, не восстанавливаются автоматически.
3. **Критично:** в v0.1 данные существовали только в памяти. После перезапуска терялись.
4. **Высокий риск:** первоначальный учёт не имел обособленного происхождения клонов, версий среды, партий, контроля операций и отката.
5. **Высокий риск:** временная подпись debug APK на разных раннерах GitHub Actions мешает обновлению поверх предыдущей установки. Добавлена конфигурация стабильной подписи через секреты (нужна настройка владельцем).
6. **Высокий риск:** сам факт существования рецепта не доказывает, что он фактически применён в указанном составе. Разделены рецепт, его версия, партия и фактически отмеренные количества.

## Дополнительные компоненты

- **Фото:** добавление из системного файлового выбора, хранение копии в приложении, хронология и включение оригиналов в ZIP. **Не проверено на физическом телефоне.**
- **Эксперименты:** регистрация гипотезы и назначение контейнера в группу. **Нет** полноценного мастера дизайна опыта, результатов по группам и p-value/интервалов.
- **Импорт CSV из Excel/Google Sheets:** читает только UTF-8 CSV c `;` и точным набором колонок, создаёт новую версию-черновик без переписывания истории. **Не** является автоматическим подключением к аккаунту Google.
- **События/аварии:** инциденты с типом, временем, произвольной заметкой и необязательной связью с одним контейнером. Нет автоматического поиска затронутого оборудования и партий по времени.
- **Помощь «?»** для сложных технологических терминов; обозначения P0/P1... скрыты с обычных экранов, остаются в этикетке и расширенной истории.

## Принципиальные слабые места, которые остаются

1. **Android-совместимость и качество UI**: без реальной компиляции и испытания могут остаться ошибки API, отображения форм, разрешений камеры, работы с файлами. Это первоочередной барьер.
2. **Подпись APK**: без постоянного ключа обновления способны конфликтовать даже при правильном `versionCode`. До загрузки реальных данных нужна проверенная стратегия подписи.
3. **Редактирование ошибок**: исправления количества/статуса пишутся в журнал, однако нет полного обратимого механизма событийной отмены и удаления неправильного дочернего пассажа.
4. **Массовое производство**: сотни/тысячи контейнеров потребуют массового сканирования и действий, а не индивидуальных диалогов.
5. **Аналитика**: повторные осмотры одних и тех же контейнеров могут искажать оценки независимых повторностей; статистический модуль требует модели опытных единиц, а не только суммирования.
6. **Фактические рецептуры**: пользователь сам вводит состав. Наличие математического калькулятора не подтверждает безопасность и пригодность протокола; недопустимо автоматически придумывать дозировки гормонов.
7. **Питательные компоненты**: подтверждение, что Babio MS уже содержит сахарозу и агар, сделано пользовательским флагом. Нужна проверка этикетки каждого производителя, чтобы избежать двойного внесения.
8. **Резервное копирование**: ручное и не зашифрованное; важно периодически выполнять тестовое восстановление на отдельном устройстве. Нет облачной автоматизации.
9. **Локальная база**: сейчас синхронные запросы. На большом массиве операций потребуется отдельный поток/DAO, пагинация и профилирование.
10. **Склад/себестоимость**: даже при включённых продажах прибыль не вычисляется достоверно без расхода материалов, оплаты труда, электричества, потерь, амортизации и постоянных затрат.
11. **Идентификация и происхождение**: один ребёнок имеет одного родителя. Для объединения материала из нескольких независимых линий нужна связь многие-ко-многим с указанием неопределённости.
12. **Безопасность**: архивы содержат коммерческие данные без шифрования. GitHub-проект публичный; пользовательские данные и секреты ни при каких условиях не загружать в репозиторий.
