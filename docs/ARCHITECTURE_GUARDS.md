# Диковерия LAB — неизменяемые правила разработки

**Источник:** код Android на текущей ветке main, ТЗ Issues #4/#3/#1. Не путать UI-дизайн с сохранением данных.

## Идентичность приложения и безопасность
- Сохранять package/applicationId и постоянный сертификат подписи. Секрет `LAB_SIGNING_BUNDLE_B64` только в release workflow и никогда в PR.
- Не допускать разрушающих миграций `SQLiteOpenHelper`, проверять поддерживаемые резервные копии; хеши и тесты миграции.
- Любой неочевидный переход данных — отдельная транзакция с откатом при ошибке.

## Модель биоматериала
- `cultures.quantity` — историческое/операционное число объектов со связанным `quantity_kind`. `culture_measurements` — **независимые** измерения `explants`, `shoots`, `plants`, `contaminated`. Null — «не измерялось», 0 — измеренный ноль.
- Обнаружен дефект: `addCultureQuick` выбирает единый quantity по `plants > shoots > explants`, а split/merge считают его физическим остатком. Не умножать/складывать разные биологические категории и не выбирать категорию молча.
- Если старый тип происхождения неизвестен, явно показывать неопределённость и спрашивать тип действия, не угадывая.
- Пересадка/деление/слияние меняют только корректно указанный операционный баланс. Факт измерения не равен изменению количества, а потери, размножение, исправление и продажа — разные операции.
- У операции должна быть родительская и дочерняя связь, время события, время регистрации, old/new values, причина и источник.

## Рецептуры
- `recipes` содержит версии; `cultures.medium_recipe_id` — прямое назначение рецептуры. `medium_batch_id` — необязательная история конкретного приготовления.
- Нельзя требовать batch_id для пересадок или менять среду молча; дочерняя культура получает явное назначение, историю его выбора и отсутствие потери родительской прослеживаемости.
- Отражать рецептуру и конкретную версию, сохранять исторические составы и предотвращать двойной счёт агар/сахар в готовой смеси.
- Не подставлять дозировки фитогормонов и научные выводы без источника.

## Два старых журнала
- UI `Осмотр` → events + assessments (последние могут быть привязаны к batches).
- UI `Рост и результаты` → culture_measurements (новый журнал; при создании контейнера стартовая запись).
- Ни одна ветка истории не должна «исчезать». Общее чтение данных и классификация события по источнику с сохранением старых таблиц; не подменять дату измерения датой ввода.
- Аналитика должна разделять стартовые записи, поздние осмотры и операционные события; нельзя дважды суммировать одно наблюдение или делать количественные выводы на несопоставимых группах.

## UI и навигация
- Каждый путь: screen → subsection → detail → editor; назад на один уровень с сохранением вложенного контекста, scroll и фильтров.
- На каждом экране явная кнопка со стрелкой + системный Back (включая жесты по обоим краям). Не закрывать всю карточку сразу.
- Кнопки различать ролью, иконкой, текстом, контрастом и местоположением, а не только цветом.
- Для Android Compose отделить состояние навигации от состояния формы; не забывать состояние по переключению вкладок/диалогов.
- Кнопка с видом действия не может быть пустой или неактивной без объяснения.

## Печать и этикетки
- Метка 40×12 мм — физический формат; указать DPI рендера, поля, минимальный размер текста, тихую зону QR.
- Динамические поля должны брать реальные данные; индивидуальный текст редактируемый; шаблоны хранят координаты и стиль, без наложений/невидимых элементов.
- Размер и координаты элемента в мм для одинакового результата между устройствами.
- Экспорт PNG и Android Sharesheet в NIIMBOT; наличие Bluetooth API не предполагать.
